Pairadox Synthetic demo data
    How this works: stack, ingestion method, limits

    Stack

    One static file: HTML, CSS and vanilla JavaScript. No backend, no database, no API keys. Participant data never leaves the browser tab (optional localStorage for added participants).

    Profile ingestion

    LinkedIn and Instagram block automated access behind logins and anti-bot controls, and this app does not try to get around them. It records the two URLs the participant supplies, but does not fetch them. The participant pastes the text visible on their own profile (LinkedIn headline and About; Instagram bio and captions). A rule-based extractor then pulls out interests, values, relationship intent, location and stated preferences, and every item carries the sentence it came from and which source it came from. Anything not supported by text is left blank and listed under uncertainties. Images are not analysed.

    Agents

    Each participant gets an Agent object that can read only its own profile. The two agents in a pair trade eight structured messages (introduction, logistics, values, verdict). An agent learns about the other person only from the payloads it receives, then scores from its own side using five weighted dimensions: interests 30%, values 25%, relationship intent 20%, lifestyle 15%, location 10%. Missing data scores a neutral 50 and is shown as unknown, which lowers the evidence-coverage figure. A stated intent clash (serious vs casual) caps the mutual score at 55. Mutual score = 0.6 × average + 0.4 × the lower of the two agents' scores.

    What is not real

    The agent dialogue is generated from templates filled with extracted facts. There is no language model in this deployment, so the conversation is a transparent protocol rather than open-ended chat. The built-in participants are synthetic and clearly labelled. Age, gender, orientation and who is open to dating whom are not modelled; the demo assumes every pair is a valid candidate.
